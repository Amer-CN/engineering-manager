### PowerShell 替换陷阱

- **CRLF vs LF**: `.Replace` 必须用 CRLF (`[char]13 + [char]10`) 才能匹配多数源码文件; AGENTS.md, CHANGELOG.md 之类文档可能是 LF-only
- **`*` 在双引号字符串**: PowerShell 把 `**` 当乘法, here-string 里也要用单引号 `@'...'@`
- **`${var}` 在双引号字符串**: PowerShell 7 解析有问题, 用 `.Replace()` 替代 `${}` interpolation
- **BOM**: `[System.IO.File]::WriteAllText` 默认 UTF-8 with BOM, 用 `[System.Text.UTF8Encoding]::new($false)` 避免

### git 约束

- mimo 跑时 .git 被改名 .git-mimo, 跑完会恢复; 如果 mimo crash, 手动 `Rename-Item .git-mimo .git`
- `git add -A` 然后 reset 单个文件用 `git reset HEAD <file>`
- package-lock.json 在 .gitignore 里 (用 `git add -f` 强制)
- 没有 origin remote, `git push` 会失败

## 6. 经验教训 (本窗口累积)

### mimo 适配模式 (n=5)

- **必过**: 单文件 React patch, 含新建子文件 (100% 一次过)
- **必败**: 任何 git 命令 (wrapper 把 .git 改名触发 EEXIST)
- **高风险**: 5+ min 任务, shell 复杂命令

### PowerShell 中文路径陷阱

- `-replace` 单引号模式 + 中文路径不工作, 用 `.Replace()` literal
- 反引号 + unicode 被 PowerShell 当 unicode escape, 写反引号内容用 here-string
- `${var}` interpolation 解析有时失败, 用 string concatenation

### 项目工程经验

- **拆超大组件前先看 hook 依赖**: InvoiceForm 拆分前要先确认 useInvoiceAmounts hook 透传方式
- **CI 红绿灯要包括 type check**: tsc 错误累积起来比 lint 错误更隐蔽, 加进红绿灯能强制 type-safe
- **mimo 不需要你写 git 命令**: mimo wrapper 把 .git 改名, 跑完恢复, 这层隔离反而保护了 git
