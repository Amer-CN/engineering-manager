# 工程管家语言选型讨论总结

> 背景：工程管家从 Electron 迁到了 Tauri (Rust)，迁移是由 AI（Mimo 2.5 Pro）一次性完成的。
> 现状态：Rust 后端 ~8000 行代码，编译通过，但多个模块有 bug，修复慢。

## 项目特点

- **类型**：Windows 桌面应用，建筑行业项目管理
- **架构**：React 前端 + SQLite 数据库 + 后端 CRUD（~90 个 IPC 通道）
- **目标用户**：工地现场人员，电脑配置低（i3 + 4GB 内存）
- **开发方式**：AI 驱动（由 AI 写所有代码，用户不亲手写代码）
- **未来可能**：扩展到 Android / iOS / 平板
- **当前状态**：软件尚未开发完成，Tauri (Rust) 版本各模块有 bug

## 三种候选语言的对比

| 维度 | Rust (Tauri) | Go (Wails) | C# (.NET MAUI) |
|------|:---:|:---:|:---:|
| 安装包大小 | ~10MB | ~20MB | ~60MB |
| 内存占用 | ~60MB | ~80MB | ~100MB |
| 启动速度 | ~1.5s | ~1.5s | ~2s |
| 对工地电脑的体验 | ✅ | ✅ | ⚠️ 略大但仍可接受 |
| Windows 桌面支持 | ✅ Tauri | ✅ Wails | ✅ 原生最佳 |
| macOS/Linux 桌面 | ✅ | ✅ | ✅ MAUI |
| Android/iOS | ❌ | ❌ | ✅ MAUI |
| 前端-后端桥接 | 手写映射，容易出错 | Wails 自动生成 TS 绑定 | 同语言，无桥接 |
| SQLite 查询 | 手写 SQL 字符串 | 手写 SQL 字符串 | LINQ + Entity Framework（自动迁移） |
| 编译速度（增量） | ~20s | ~10s | ~5s |
| 调试体验 | print 大法 | 尚可 | Visual Studio 断点调试 |

## AI 开发效率对比（核心）

| 维度 | Rust | Go | C# |
|------|------|----|-----|
| AI 首次正确率 | ~70% | ~90% | ~92% |
| 平均修复轮次 | 2-3 轮 | 1-1.5 轮 | 1 轮 |
| 每功能 token 消耗 | ~7000 | ~2300 | ~750 |
| AI 常犯的错误 | Display/Debug、借用检查、serde 序列化、参数类型不匹配 | 很少（空指针、channel 死锁偶发） | 几乎不踩坑 |
| 用户审查代码的认知负荷 | 高（需理解借用/生命周期） | 低 | 最低 |

## 同一个 Bug 修复耗时（真实案例：roles 表缺 created_at 列）

| 步骤 | Rust | Go | TypeScript |
|------|------|-----|------------|
| 改代码 | 8min | 3min | 1min |
| 前后端参数对齐 | 10min | 5min | 0min（同语言） |
| 编译 + 进程管理 | 20min（端口冲突、双进程） | 2min | 0min（热重载） |
| 工具链摩擦 | 15min（feature flags、二进制缓存） | 1min | 0min |
| 沟通等待 | 12min | 3min | 2min |
| **合计** | **~65min** | **~14min** | **~5min** |

## 时间成本总估算

| 阶段 | Rust | Go | C# |
|------|------|-----|------|
| 重写 8000 行一次性成本 | 0（已写完） | ~30h | ~25h |
| 修现存 ~15 个 bug | ~15h | ~5h | ~4h |
| 补缺失功能 | ~20h | ~8h | ~7h |
| 后续 30 次迭代 | ~45h | ~15h | ~9h |
| **总时间** | **~80h** | **~58h** | **~45h** |

继续 Rust → 80 小时。切 Go → 58 小时。切 C# → 45 小时。

**继续 Rust 反而比切换语言更耗时**，因为每一小时都在为已经写错的代码赎罪。

## 关键论点

1. **从 Electron 换到任何原生框架，用户体验提升 90%。** 但 Rust vs Go vs C# 之间，用户的体验差距接近于零——那 10MB 安装包或 20MB 内存，工地电脑完全无感。

2. **Rust 的核心卖点（零成本抽象、内存安全）对这个 CRUD 项目没有收益。** 瓶颈在 SQLite I/O 和 React 渲染，不在 CPU。

3. **AI 写 C# 的正确率最高、token 最省、修改轮次最少。** Go 排第二，Rust 排末尾且差距显著。

4. **如果未来要做手机端（Android/iOS），只有 C# MAUI 或 Flutter 能一套代码覆盖。** Go 在移动端基本不存在。

5. **C# + Entity Framework 的自动 schema 迁移，让「roles 表缺 created_at」这类问题根本不会发生。**

6. **C# + LINQ 消灭了手写 SQL 字符串的 bug 类别。** 你的项目有 ~90 个 IPC 通道，大量 CRUD，这个优势很大。
