# 教不会，就不教了

故事是这样的。

上周五，部门聚餐。

酒过三巡，项目经理老张突然问我，听说你自己做了个软件？

我说是。

他说，能不能教教我？我也想搞一个。

我当时特别高兴。终于有人主动问了。

然后我打开手机，给他看截图。他看了半天，说，这玩意怎么装？

我说，你得先装个Claude Code，这是个命令行工具，然后配置环境变量，再装Node.js，然后npm install，然后npm run dev。。。

他的表情，从好奇变成了茫然，从茫然变成了放弃。

他说，算了，我还是用Excel吧。

🪨

我当时心里特别难受。

不是因为他拒绝了，是因为我知道，他说的是实话。

老张今年四十七了，在工地上干了二十多年。他能一眼看出混凝土的标号对不对，能凭手感判断钢筋的间距够不够。他带出来的项目经理，现在好几个都是公司的骨干。

但你让他打开命令行，敲几行代码？

这不是他的领域。

就像你让我去工地，我也分不清C30和C40有什么区别。

我突然意识到一件事。

我一直以为，问题在于"他们不愿意学"。

但其实不是。

问题是，我给的东西，不对。

🛠️

你想想看，你去饭店吃饭，厨师跟你说，这道菜你得先学颠勺，再学调味，再学火候，最后才能吃。

你什么反应？

你肯定说，我就想吃口饭，你告诉我怎么吃就行，我为什么要学怎么做？

我跟老张说的那堆东西，Claude Code、Node.js、npm，在他听来，就跟"先学颠勺"一样。

他不需要知道这些。

他只需要知道，打开软件，点哪里，能干什么。

但我给不了他这个东西。

因为我做的软件，是一个本地运行的桌面应用，需要安装、需要配置、需要一定的技术基础才能用。

对于我来说，这些都很简单。

对于他来说，这些是天书。

这就是问题所在。

💡

后来我想明白了一件事。

我做这个软件，初衷是什么？

是为了解决我自己的问题。

几十个项目文件夹，Excel、PDF、图片混在一起，我需要一个工具来管理这些。我跟AI聊了聊，它帮我做出来了。

这个工具，是为我量身定做的。

但"为我量身定做"，就意味着"别人用不了"。

因为每个人的工作习惯不一样，每个人的痛点不一样，每个人的电脑环境不一样。

我用着顺手的东西，别人可能觉得反人类。

这就像你给自己打了一把锤子，特别好使。但你不能把这把锤子塞给别人，说，你看，我这锤子多好，你用吧。

人家可能需要的是扳手，或者螺丝刀。

所以我现在想明白了。

我不教了。

不是放弃他们，是换个思路。

我自己用好这把锤子，把自己的工作效率提上去。等他们看到我的效果了，自然会问。

如果他们不问，那也没关系。

我把我用这个工具的过程记录下来，写成文章。有人看到了，觉得有意思，愿意试一试，那就行了。

就像你现在看到的这样。

🌱

说到记录，我最近发现一个很有意思的事。

我写这些文章的时候，AI帮了我大忙。

不是那种"帮我写文章"的帮忙，是那种"帮我理清思路"的帮忙。

比如今天这篇，我一开始想写"为什么我教不会他们"。我跟AI聊了聊我的困惑，它问我，你确定问题在"他们不愿意学"吗？

我想了想，好像不是。

它又问，那你觉得问题在哪？

我说，可能是我给的东西不对。

它说，那你想想，他们需要什么？

我想了想，他们需要的是一个简单的、不需要配置的、打开就能用的工具。

然后文章的思路就出来了。

我不是在写文章，我是在跟AI聊天，聊着聊着，文章就出来了。

这种感觉太爽了。

就像你以前写东西，要先列提纲，再打草稿，再修改。现在你只要跟AI说，我想写个东西，主题是这个，它帮你理清思路，你顺着思路往下写就行了。

当然，最终写出来的还是我自己的话，我自己的经历，我自己的感受。

AI只是帮我把散乱的想法串起来。

这就像你有一个特别会聊天的朋友，你跟他说你的烦恼，他不给建议，就是听你说，偶尔问你两个问题。

你说着说着，自己就想明白了。

AI就是那个朋友。

✨

回到老张的事。

聚餐结束后，我回家想了很久。

我决定换一种方式帮他。

我不教他装软件、配环境这些东西了。我直接把我做的东西，做成一个简单的使用说明。

打开软件，点这里，能看到什么。点那里，能干什么。

就像你买了一个新家电，说明书上写的那样。

第一步，插电。第二步，按开关。第三步，选模式。

不需要知道冰箱的压缩机怎么工作，你只需要知道，按这个按钮，它就制冷。

我把我做的软件，也做成这样的东西。

到时候给老张，他一看就懂，一用就会。

他不需要知道软件是怎么做出来的，他只需要知道，怎么用。

这，才是他需要的。
